Your First Project

Kuwantima Design System
Fork the project, run it, change something, push it. Your first commit in under 30 minutes.
Prerequisite: complete 01 Your Toolkit first.
Step 1

Fork the Project

"Forking" creates your own independent copy of the project on GitHub. The original is completely unaffected by anything you do — think of it as photocopying a book so you can write in the margins.

1 Go to the Kuwantima repository
https://github.com/Votskwani/Kuwantima
2 Click the "Fork" button

It's in the top right corner of the page.

3 Click "Create fork"

On the next page, leave all the defaults and click Create fork.

You now have your own copy at github.com/YOUR-USERNAME/Kuwantima.

Step 2

Download It to Your Computer

Now we'll "clone" your fork — that means downloading all the project files so you can work on them locally.

1 Copy your fork's URL

On your fork's GitHub page, click the green Code button and copy the HTTPS URL.

2 Open a terminal and clone

Open Command Prompt and run (replace YOUR-USERNAME with your GitHub username):

git clone https://github.com/YOUR-USERNAME/Kuwantima.git
cd Kuwantima

You now have all the project files on your computer.

Ask Claude
If you get a "permission denied" or authentication error, open the Claude panel in Visual Studio (or claude.ai in your browser) and paste the error message. Claude can walk you through setting up Git credentials.
Step 3

Open and Run It

Let's make sure everything works before changing anything.

1 Open the solution in Visual Studio

In Visual Studio, go to File > Open > Project/Solution and navigate to the folder you just cloned. Open the file called Kuwantima.slnx.

2 Set the startup project

In the Solution Explorer panel (usually on the right), right-click Kuwantima.Sandbox and choose Set as Startup Project.

3 Run it

Press F5 (or click the green play button at the top). A window will open showing the design system — buttons, toggles, sliders, all styled with the glass-glow theme.

Click around and explore! Try toggling between light and dark mode with the theme switch. Close the window when you're done.

If the build fails
Don't panic — ask Claude! Open the Claude panel in Visual Studio and say: "The build failed — here's the error" and paste the error from the Output or Error List window. Claude can see your project and will tell you exactly what to fix.
Step 4

Make Your First Change

Let's change a color so you can see the edit-run cycle in action.

1 Open the theme resources file

In Solution Explorer, navigate to:
Kuwantima > Theme > KuwantimaThemeResources.axaml

Double-click to open it.

2 Find KuwantimaAccentBorder

Press Ctrl+F to open Find, and search for KuwantimaAccentBorder. This controls the glow color on selected items.

3 Change the color

Change the hex color value to something you like. Try one of these:

  • #FF6A0DAD — purple
  • #FF00CED1 — teal
  • #FFDC143C — crimson
4 Save and run

Press Ctrl+S to save, then F5 to run. See your change! Toggle between light and dark mode to see it in both themes.

Ask Claude
Want to know what other colors you can change? Ask Claude in the VS panel: "What are all the custom colors defined in KuwantimaThemeResources.axaml and what does each one control?"
Step 5

Save Your Change to GitHub

When you're happy with a change, you "commit" it (save a snapshot) and "push" it (upload to GitHub).

1 Open a terminal

In Visual Studio, go to View > Terminal to open a terminal panel at the bottom. Make sure you're in the Kuwantima folder.

2 Stage, commit, and push

Type these three commands, one at a time:

git add .
git commit -m "Change accent color"
git push
3 Verify on GitHub

Go to your fork on GitHub and refresh the page — you'll see your commit!

What just happened:

  • git add . — selects all changed files
  • git commit -m "..." — saves a snapshot with a short description
  • git push — uploads it to your GitHub fork
Ask Claude
If git asks for credentials or gives an error on push, paste the message into Claude (in VS or in the browser). It will walk you through authentication setup step by step.
Step 6

Make It Yours

You've forked Kuwantima and made your first change. Now it's time to think about making this design system truly your own — starting with giving it a name.

The Name Behind the Project

Every project in this family carries a Hopi name. The Hopi are an indigenous people of northeastern Arizona whose language, culture, and worldview are deeply interwoven with the land, the ceremonies, and the journey of life.

Understanding the naming story helps you appreciate what you're building on — and inspires what you'll name your own work.

Kuwantima — Beautiful Surroundings / All the Colors of the Rainbow

From kuwan- (bright, vibrant, varied colors) + -tima (area, space, surroundings). It evokes a landscape where a full spectrum of colors is visible all around — the painted desert, ceremonial regalia, sacred corn in blue, yellow, red, and white. A name that represents harmony, beauty, and the diversity of life.

This is what the design system aspires to be: a rich palette of visual controls that brings color and life to an application.

Votskwani — The Straight Path

The GitHub organization name. In the Hopi worldview, the "straight path" is both physical and spiritual — it represents integrity, clear direction, and the one-hearted approach to life. Walking the straight path means honesty, reliability, and staying true to purpose without distraction or compromise.

This frames how the project is maintained: with clear intent, open contribution, and no hidden agendas.

Tunatya — Vision / The Bridge

The parent project that Kuwantima will be integrated into. Tunatya means vision, goal, or aspiration — the act of looking toward something. It's also described as "the bridge between us — exists only while both sides hold it." Tunatya is the larger vision; Kuwantima is its visual expression.

Navoti — Wisdom Seated in Harmony

The name of the design system family. Navoti means knowledge or wisdom — but not knowledge as accumulated facts. You don't collect navoti. You arrive at it. It's awareness seated in rightness.

Sumi'nangwa — Working Together with Common Purpose

The name for the collaboration itself. Not labor divided — labor shared. The effort exists in the joining, not in the portions. This is what we're doing right now.

In Hopi culture
Names are not just labels. They are bestowed by a "naming mother" from a different clan during initiation, and they reflect the clan of the person giving the name. They carry intention, connection to the natural world, and a vision for the person's path. When you name your project, you're continuing that spirit — choosing a name that carries meaning for what you're building.

Choosing Your Own Name

When you're ready to make this fork truly yours, you'll want to give it a name that means something to you. It could be:

1 Think about what your design system represents

What colors, what feeling, what story? Kuwantima is "all the colors of the rainbow" — what is yours?

2 Ask Claude for help

Claude can help you brainstorm names. Try asking in the VS panel or at claude.ai:

"I'm naming a UI design system. The visual style is [describe your vision]. Can you help me brainstorm names that feel meaningful?"

3 Rename it when you're ready

When you've chosen a name, ask Claude to help you rename the project:

"I want to rename this project from Kuwantima to [your name]. Can you help me update all the namespaces, file names, and references?"

Claude can see your entire project and will walk you through every file that needs to change. Don't rename anything manually — let Claude handle the tedious parts so nothing gets missed.

No rush
You don't have to rename anything right away. Work with it as "Kuwantima" for as long as you like. The name will come when the project starts to feel like yours.
Step 7

Keep Going

You've made your first change and pushed it. Here's where to look when you want to do more.

Where to Find Things

I want to... Look in...
Change colors and themes Kuwantima/Theme/KuwantimaThemeResources.axaml
Change how a button looks Kuwantima/Styles/KuwantimaButton.axaml
Change how a checkbox looks Kuwantima/Styles/KuwantimaCheckBox.axaml
Change any control's style Kuwantima/Styles/Kuwantima{ControlName}.axaml

The sandbox app is your playground — every time you change a style, run it to see the result. There are no tests to run; if it looks right, it is right.

Useful Git Commands

You only need a handful of commands for day-to-day work:

Command What it does
git status Shows what files you've changed
git add . Stages all changes for commit
git commit -m "message" Saves a snapshot
git push Uploads to GitHub
git pull Downloads latest changes from GitHub
git log --oneline Shows recent commit history

Project Structure at a Glance

Kuwantima/ Theme/ -- colors, brushes, theme definitions Styles/ -- how each control looks Kuwantima.Sandbox/ -- the demo app you run to see your changes Views/Pages/ -- each page in the sandbox

Troubleshooting

"DLL is locked" or build fails after running the sandbox

Close the sandbox window before trying to build again. The running app locks the files.

Git asks for my password every time

Run this once to save your credentials:

git config --global credential.helper store

Or install GitHub CLI and run gh auth login.

I broke something and want to start over

You can always delete your local folder, go to your fork on GitHub, delete it, and re-fork from the original. Clean slate, no harm done.

I want to get updates from the original project 
git remote add upstream https://github.com/Votskwani/Kuwantima.git
git pull upstream master

This pulls in any new changes from the original Kuwantima repo.

When in doubt, ask Claude
For any problem not listed here, just describe what happened to Claude — either in the Visual Studio panel or at claude.ai. Paste the error message, explain what you were trying to do, and Claude will help you fix it. There is no problem too small to ask about.
