For the teacher

Chapter 1

Before You Sit Down

Confirm their environment is ready before starting the walkthrough. Debugging installs mid-lesson kills momentum.

The Four Prerequisites

1 Git
https://git-scm.com/downloads

Windows installer defaults are fine.

2 .NET 10 SDK
https://dotnet.microsoft.com/download
3 A code editor

Visual Studio Community is what 01-your-toolkit.html walks them through. VS Code or Rider also work if they prefer.

4 A GitHub account
https://github.com/signup

Verify Their Setup

Have them open a terminal and run these two commands:

git --version
dotnet --version

Both should print a version number. If either says command not found, the install isn't on their PATH yet.

Quick fix
Restart the terminal first — PATH changes don't propagate to already-open windows. If still broken, reinstall with the "Add to PATH" option checked.
Chapter 2

Fork on GitHub

Walk them through creating their own independent copy of the repo on GitHub.

1 Open the Kuwantima repo
https://github.com/Votskwani/Kuwantima
2 Click the Fork button (top right)
3 Leave the defaults

On the "Create a new fork" page, the defaults are fine. They can rename the repo later if they want.

4 Click Create fork

They now have their own copy at github.com/THEIR-USERNAME/Kuwantima.

What to explain

A fork is a full, independent copy. Nothing they do affects your original. They own it completely — rename it, delete it, wreck it, doesn't matter. This is the safety net that makes every other step low-stakes.

Chapter 3

Clone to Their Computer

Download their fork locally so they can open it in their editor.

1 Copy their fork's HTTPS URL

On their fork's GitHub page, click the green Code button and copy the HTTPS URL.

2 Clone and enter the folder 
git clone https://github.com/THEIR-USERNAME/Kuwantima.git
cd Kuwantima
Watch for this
If they accidentally clone your URL (Votskwani/Kuwantima) instead of their fork, git push will fail later with "permission denied." If that happens, re-clone from their fork's URL.
Chapter 4

Run the Sandbox

Prove everything works before changing anything. This is the moment they see that the project is real and running on their machine.

1 Run from the project root 
dotnet run --project Kuwantima.Sandbox
2 Let them click around

The sandbox window should open. Walk them through the pages — Buttons, Inputs, Toggles, Feedback, Containers, Theme Preview, Documents. Toggle light/dark. This is their visual test harness.

The loop to name out loud

Every change they make follows the same rhythm: edit → save → close → run → see. Naming the loop now gives them a mental model they'll use every day.

Chapter 5

Their First Edit

Pick something visible and low-risk. The goal is confidence, not complexity.

Good First Targets

Target Where
Accent color Kuwantima/Theme/KuwantimaThemeResources.axaml — find KuwantimaAccentBorder and swap the hex
Glow color Same file — find KuwantimaGlowBrush and try a different hue

The Edit Loop

1 Open the file in their editor
2 Change one color value
3 Save the file
4 Close the sandbox window

This matters — the running sandbox locks DLLs, so you must close it before rebuilding.

5 Run the sandbox again 
dotnet run --project Kuwantima.Sandbox
Teaching moment
The "close before rebuild" step is the most common first stumble. Call it out explicitly the first time, and they'll never forget it.
Chapter 6

First Commit and Push

Save the change to their fork on GitHub. This is the milestone moment.

1 Stage, commit, and push 
git add .
git commit -m "Change accent color to purple"
git push
2 Refresh their fork on GitHub

Their commit will appear on the page. This is a real milestone — acknowledge it. They just completed the full professional development loop.

What Each Command Does

Command What it does
git add . Stages all changed files (selects what to include)
git commit -m "..." Saves a snapshot with a short description
git push Uploads the commit to their GitHub fork
If Git asks for credentials every time
Set up a credential helper so they don't have to re-authenticate: 
git config --global credential.helper store
Or install GitHub CLI and run gh auth login.
Chapter 7

Customization Paths

Once the loop clicks, here's where to send them next.

Goal Where to look
Change all colors Kuwantima/Theme/KuwantimaThemeResources.axaml
Modify a control style Kuwantima/Styles/Kuwantima{Control}.axaml
Add a new sandbox page Follow the checklist in CLAUDE.md
Rename the project Repo settings on GitHub + namespaces in code
Publish as their own NuGet package Update .csproj metadata + set up their own API key
Pull in your latest updates later 
git remote add upstream https://github.com/Votskwani/Kuwantima.git
git pull upstream master
Chapter 8

Tone Tips

The walkthrough goes better when you hold the posture of a guide, not a driver.

Let them drive the keyboard

Resist the urge to reach over and type. Muscle memory only builds through their own hands.

Celebrate the first successful push

It's a real milestone — the moment their work lives on GitHub for the first time. Mark it.

Treat breakage as learning

Error messages are information, not failure. The habit of reading them calmly is one of the most valuable things you can model.

"You can always re-fork"

The ultimate safety net for a beginner: delete the local folder, delete the fork on GitHub, fork again from the original. Clean slate, no harm done. Say this out loud — it takes all the fear out of experimenting.

Common Stumbles Reference

Problem Fix
"Permission denied" on push They cloned your repo, not their fork. Re-clone from their fork URL.
"DLL is locked" on build Close the sandbox window before rebuilding.
Git asks for credentials every time git config --global credential.helper store or use GitHub CLI.
They accidentally edit master Fine — they own the fork. No protection rules needed for solo work.
They want your latest updates Add upstream remote and git pull upstream master (see Chapter 7).

Session Checklist

Use this during the walkthrough
  • Prerequisites verified (git --version + dotnet --version both print)
  • Fork created on GitHub
  • Fork cloned locally
  • Sandbox runs and they've clicked through the pages
  • First color edit made and visible in the sandbox
  • First commit pushed and visible on GitHub
  • Pointed at customization paths for next steps
